# Product Requirements Document (PRD)

## Ultra-Premium Cinematic AI/Data Science Portfolio

### 1. Product Overview

Build a premium personal portfolio that presents the candidate as an
AI/Data Science engineer through an immersive, cinematic digital story
rather than a conventional resume website.

The existing Hero Section is approved and must remain completely
unchanged. All redesign work applies only to the sections after the
hero.

### 2. Product Vision

Create a portfolio that feels like: - Apple product storytelling -
Premium editorial design - Interactive AI laboratory - Cinematic case
study - Neo-glass / neomorphic interface - High-end digital product
experience

The visitor should experience a continuous story rather than a sequence
of generic portfolio sections.

### 3. Primary Goals

1.  Preserve the existing hero exactly.
2.  Replace ordinary portfolio sections with cinematic storytelling.
3.  Present skills as an interactive capability system instead of skill
    cards.
4.  Present projects as immersive case studies instead of project cards.
5.  Demonstrate technical thinking through animated architectures and
    pipelines.
6.  Establish a strong personal identity and engineering narrative.
7.  Use sophisticated scroll-driven motion and micro-interactions.
8.  Maintain an 80% white/light visual foundation with approximately 20%
    strategic accent color.
9.  Deliver a responsive, accessible and performant experience.
10. Make the portfolio memorable and differentiated from template
    portfolios.

### 4. Target Audience

-   Recruiters
-   Hiring managers
-   Data Science teams
-   AI/ML engineering teams
-   Technical interviewers
-   Potential collaborators

### 5. Core User Journey

Hero → Cinematic transition → Who I Am → How I Think → Capability System
→ How I Build → Projects → Behind the Model → Evolution → Education →
Verified Knowledge → What's Next → Contact

### 6. Section Requirements

#### 6.1 Hero Protection

The hero is read-only: - No layout changes - No asset changes - No
typography changes - No animation changes - No spacing changes - No
color changes - No content changes

#### 6.2 Cinematic Transition

Introduce the next chapter using large editorial statements such as: "I
DON'T JUST BUILD MODELS." "I BUILD SYSTEMS THAT UNDERSTAND." "DATA →
INTELLIGENCE → EXPERIENCE."

Requirements: - Large typography - Whitespace - Scroll-controlled
reveal - Subtle technical layers - Depth/parallax - Smooth transition
from hero

#### 6.3 Who I Am

Present identity through editorial storytelling.

Core message: "ENGINEERING INTELLIGENCE WITH PURPOSE."

Include: - Profile/portrait visual - Glass object - Technical metadata -
Subtle grid - Spatial depth

#### 6.4 How I Think

Create an animated intelligence pipeline:

DATA → UNDERSTANDING → FEATURES → MODEL → EVALUATION → DEPLOYMENT →
INTELLIGENCE

Each stage should activate progressively during scroll.

#### 6.5 Capability System

Do not use skill grids or progress bars.

Create an interactive central intelligence object surrounded by: -
Data - Machine Learning - Deep Learning - Computer Vision - NLP -
MLOps - Cloud - Analytics

Hovering/selecting a capability should reorganize the surrounding system
and reveal related technologies.

#### 6.6 How I Build

Create a living architecture:

DATA → PREPROCESSING → FEATURE ENGINEERING → MODEL → API → DEPLOYMENT →
USER

Animate: - module appearance - connection drawing - signal flow - active
states

#### 6.7 Projects

Projects must be cinematic case studies.

Primary projects: 1. Crop Yield Prediction 2. Real-Time Obstacle
Detection 3. Rice Leaf Disease Detection 4. Handwritten Digit / MNIST 5.
Bank Marketing

Each project should tell: Problem → Data → Approach → Model →
Deployment/Output → Result

Key metrics such as R² 0.85 and 88% accuracy should become visual
narrative moments, not ordinary statistic cards.

#### 6.8 Project Navigation

Create a floating glass chapter navigator: 01 CROP YIELD 02 OBSTACLE AI
03 RICE VISION 04 MNIST 05 BANK MARKETING

Active project should be visually dominant.

#### 6.9 Behind the Model

Show technical architecture through spatial glass modules and animated
signal paths.

#### 6.10 Evolution

Replace a conventional timeline with a cinematic journey: ENGINEERING →
PROGRAMMING → DATA → MACHINE LEARNING → AI → SYSTEM DESIGN

#### 6.11 Education

Present Electronics & Communication Engineering as an engineering
foundation connected to modern AI/data work.

Narrative: "ENGINEERING TAUGHT ME HOW SYSTEMS BEHAVE." "DATA TAUGHT ME
HOW SYSTEMS LEARN."

#### 6.12 Verified Knowledge

Present certifications as a floating digital archive rather than
certificate cards.

#### 6.13 What's Next

Present future interests as floating interactive typography: -
Generative AI - Computer Vision - Agentic Systems - RAG - MLOps - 3D Web
Experiences

#### 6.14 Contact

Final cinematic statement: "LET'S BUILD WHAT COMES NEXT."

Use one premium glass interaction: "START A CONVERSATION →"

### 7. Visual Requirements

Visual ratio: - \~80% white/light neutral - \~20% accent color

Preferred accents: - muted electric blue - subtle cyan - refined gold -
graphite

Use: - frosted glass - translucent surfaces - soft borders - inner
highlights - realistic depth - subtle reflections - restrained shadows -
light grain

Avoid: - dark cyberpunk - excessive neon - excessive gradients -
repetitive glass cards - generic dashboard aesthetics

### 8. Motion Requirements

Use: - scroll-driven storytelling - progressive reveals - parallax
depth - magnetic interactions - glass physics - text choreography -
cursor-responsive lighting - signal-flow animation - section morphing

Motion must feel: - smooth - physical - restrained - premium -
intentional

### 9. Responsive Requirements

Desktop, tablet and mobile must all be supported.

Mobile must be recomposed rather than simply scaled down.

Requirements: - no horizontal overflow - no overlapping content -
preserved hierarchy - usable touch interactions - reduced animation
complexity where required

### 10. Accessibility

Provide: - semantic HTML - keyboard navigation - visible focus states -
sufficient contrast - alt text - reduced-motion support - accessible
interactive labels

### 11. Success Criteria

The redesign succeeds when: - The hero remains untouched. - No major
section resembles a generic portfolio template. - Projects feel like
case studies. - Skills feel like an interactive system. - Scroll motion
creates a coherent narrative. - The visual system is predominantly
white/light. - Animations feel premium rather than excessive. - Desktop
and mobile both work reliably. - Performance remains strong. - The
visitor can understand the candidate's engineering and AI capabilities
without reading a traditional resume page.

### 12. Non-Goals

Do not: - redesign the hero - create a SaaS dashboard - add unnecessary
3D - add meaningless animation - add excessive dependencies - turn the
portfolio into a dark cyberpunk website - replace storytelling with
cards
